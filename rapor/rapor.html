Aşama 2 Mimari Seçimi ( İlk Sayfa Beyanı ):
Bu projede iki mimari yoldan 2. Yol: Web API + Arayüz mimarisi seçilmiştir.
  • Arka Uç (Web API): ASP.NET Core 8.0 (C#) ile katmanlı mimaride geliştirilmiş olup yalnızca JSON döner. Veri erişimi Repositories/YemekhaneRepository.cs ve Data/DbConnectionFactory.cs katmanlarında izole edilmiştir; Controller sınıflarında hiçbir SQL sorgusu bulunmaz.
  • Ön Yüz (Arayüz): frontend container'ı içindeki Apache 2.4 tarafından sunulan duyarlı (responsive, 400 px telefon uyumlu) HTML5 + CSS3 ve saf (Vanilla) JavaScript fetch ile geliştirilmiştir; React/Vue gibi bir çerçeve kullanılmamıştır. Apache, /api/* isteklerini ters vekil (Reverse Proxy) olarak http://uygulama:8080/api/* servisine iletir.

Aşama 2 · Uygulama Katmanları, İstek Yolu ve Okuma/Yazma Ayrımı

2.1. Bir İsteğin Uygulama İçindeki Yolu (Route → Controller → Veri Katmanı → Yanıt)

1. Tarayıcı (Fetch)
POST /api/rezervasyonlar
→
2. Apache 2.4
RewriteRule ^/api/(.*)
http://uygulama:8080
→
3. Controller
RezervasyonController.Olustur()
(SQL içermez)
→
4. Veri Katmanı

CALL sp_rezervasyon_yap
→
5. JSON Yanıt
HTTP 200 OK veya
HTTP 400 (SQLSTATE 45000)
// 1) Controller Katmanı: uygulama/Controllers/RezervasyonController.cs (İçinde SQL bulunmaz)
[Route("api/rezervasyonlar")]
public class RezervasyonController : BaseApiController
{
    [HttpPost]
    public async Task<IActionResult> Olustur([FromBody] RezervasyonOlusturDto istek)
    {
        var oturum = await AktifOturumGetirAsync(); // Redis 'oturum:{token}' doğrulaması + 30 dk TTL yenileme
        if (oturum == null) return Unauthorized(new { hata = "Rezervasyon yapmak için lütfen giriş yapın." });

        try {
            var (rezId, kesilenUcret, guncelBakiye, porsiyon) =
                await _repository.RezervasyonYapAsync(oturum.Id, istek.MenuId, istek.Porsiyon);

            oturum.Bakiye = guncelBakiye;
            await RedisService.OturumGuncelleAsync(IstekTokenGetir()!, oturum);

            return Ok(new {
                mesaj = "Rezervasyonunuz başarıyla oluşturuldu.",
                rezervasyonId = rezId, porsiyon, kesilenUcret, guncelBakiye,
                bakiyeOkumaKaynagi = "mysql-primary"
            });
        }
        catch (IsKuraliIstisnasi ex) {
            // Stored Procedure SQLSTATE '45000' Türkçe hata mesajı HTTP 400 ile arayüze iletilir
            return BadRequest(new { hata = ex.Message });
        }
    }
}

// 2) Veri Erişim Katmanı: uygulama/Repositories/YemekhaneRepository.cs
public async Task<(int RezervasyonId, decimal KesilenUcret, decimal GuncelBakiye, string Porsiyon)>
    RezervasyonYapAsync(int kullaniciId, int menuId, string porsiyon = "tam")
{
    await using var conn = await _dbFactory.OpenPrimaryConnectionAsync(); // Yazma -> mysql-primary:3306
    try {
        await using var cmd = new MySqlCommand("sp_rezervasyon_yap", conn) { CommandType = CommandType.StoredProcedure };
        cmd.Parameters.AddWithValue("@p_kullanici_id", kullaniciId);
        cmd.Parameters.AddWithValue("@p_menu_id", menuId);
        cmd.Parameters.AddWithValue("@p_porsiyon", porsiyon);
        // ... Stored Procedure çalıştırılır ve hemen ardından bakiye mysql-primary'den okunur ...
    }
    catch (MySqlException ex) when (ex.SqlState == "45000") {
        throw new IsKuraliIstisnasi(ex.Message); // Örn: "Bakiye yetersiz." veya "Kapasite dolmuştur."
    }
}

2.2. Rezervasyondan Hemen Sonra Gösterilen Bakiyenin Neden Kaynaktan (mysql-primary) Okunduğu

Replikasyon Gecikmesi (Replication Lag) ve Read-Your-Own-Writes Tutarlılığı:
MySQL kaynak-replika (source-replica) mimarisinde replikasyon varsayılan olarak asenkron (eşzamansız) çalışır. Kullanıcı rezervasyon yaptığında sp_rezervasyon_yap yordamı mysql-primary üzerinde kullanıcının bakiyesini düşürür ve işlemi COMMIT eder; ancak bu işlemin binary log (GTID) üzerinden mysql-replica sunucusuna iletilip relay log'dan uygulanması ağ veya disk yüküne bağlı olarak birkaç milisaniye ile birkaç saniye arasında gecikebilir (replikasyon gecikmesi / replication lag). Eğer rezervasyon işlemi tamamlanır tamamlanmaz kullanıcının yeni bakiyesi mysql-replica üzerinden okunsaydı, replika henüz güncellenmemiş olabileceği için kullanıcı ekranda eski (düşülmemiş) bakiyesini görebilirdi. Bu tutarsızlığı (stale read) önlemek ve Read-Your-Own-Writes tutarlılığını garanti altına almak adına, rezervasyon ve bakiye yükleme işlemlerinin hemen ardından dönen güncel bakiye doğrudan yazma işleminin yapıldığı mysql-primary sunucusundan okunmaktadır.
